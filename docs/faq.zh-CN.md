## 一、项目认知阶段

### 1. SweetGold 是什么？

SweetGold 是一个围绕蜂群模拟建立的、可复现且可审计的多智能体 AI 实验室。它把模拟、策略训练、配对种子评测、策略晋级、模型分发、可视化竞技场和决策证据连接成一条完整工作流。

### 2. 它只是一个蜜蜂小游戏吗？

不是。蜜蜂世界是一个容易观察的参考环境。项目真正研究的是：多个只能看到局部信息的智能体，怎样共享有限资源、避免冲突、管理能量，并在各自行动时形成可靠协作。

### 3. SweetGold 今天已经交付了什么？

它已经交付三层核心能力：

- **BeeSim：**确定性的种子化蜂群模拟器；
- **BeeBench：**让多个策略在相同随机种子上接受公平评测；
- **Strategy Arena：**策略并排运行、联赛、回放以及可追溯的推荐证据。

它还包含可选的 BC、PPO、CTDE 训练流水线、模型注册与哈希校验、双语文档和发布站点。

### 4. 项目最重要的价值是什么？

不是“蜂蜜分数最高”，也不是某一个独有算法，而是让策略必须通过可重复的证据才能晋级：使用同一批场景、隔离训练与最终测试、提前声明门槛、保留失败结果，并让模型和决策可以追溯。

### 5. M14、M15、M16 为什么同时出现？

它们代表不同类型的进展：

| 名称 | 当前含义 |
| --- | --- |
| M14 | 最新通过正式跨分布评测并晋级的策略 |
| M15 | 最新完成的产品工作流：根据目标与安全约束推荐或拒绝策略 |
| M16 | 最新工程里程碑：CPU、Apple MPS、NVIDIA CUDA 的显式执行与硬件证据 |

因此，M16 更新并不意味着出现了一个比 M14 更新的策略。

### 6. SweetGold 当前处于什么阶段？

`v1.2.0` 已完成本轮特性周期，项目目前处于维护模式。现阶段优先处理缺陷、安全、兼容性、可复现性、文档和发布可靠性；没有明确研究问题和预先声明评测方案的新功能会暂缓。

### 7. 谁可能从这个项目中受益？

- 想理解多智能体学习完整生命周期的学生和教师；
- 需要研究公平评测、最终测试隔离和策略晋级的 ML 团队；
- 关注模型证据、审批和审计链路的 MLOps / 治理团队；
- 希望把证据工作流迁移到机器人、物流、交通、游戏或其他仿真的研发团队；
- 需要演示可信 AI 工程实践的咨询、创新和培训团队。

## 二、初次体验阶段

### 8. 我没有 AI 背景，可以使用吗？

可以。核心模拟器、规则策略、基准和网页 Arena 只要求 Python 3.10+，不依赖 PyTorch。你可以先把它当成“多个策略在同一个蜂群世界中比赛”，再逐步理解训练和评测概念。

### 9. 最快怎样看到它运行？

在完整项目仓库中运行：

```bash
python3 main.py play --port 8080
```

然后访问 `http://127.0.0.1:8080`。这适合本地体验和研究演示，不适合直接暴露成公网多用户服务。

### 10. 我应该先看 Arena，还是先训练模型？

先看 Arena。训练不是理解项目的前置条件，而且已晋级模型可以单独下载、验证和使用。只有当你需要研究训练过程或复现实验时，才需要安装可选 ML 依赖。

### 11. 为什么两个策略一定要使用相同随机种子？

随机种子决定地图、资源和天气等初始条件。相同种子相当于让两个考生做同一张试卷，可以减少“一个策略碰巧遇到简单世界”的干扰。

### 12. 一场 Arena 比赛能证明某策略更可靠吗？

不能。一场比赛或小规模联赛适合演示和发现问题，但不能替代跨场景、足够样本量、门槛预先声明的正式鲁棒性审计。

### 13. 我在页面里看到策略胜出，是否应该立即采用它？

不应该只看排名。应同时查看目标是什么、最低存活率和最大无效动作率等约束是否满足、样本规模是否足够，以及该结论是演示结果还是正式晋级证据。

## 三、学习与教学阶段

### 14. SweetGold 适合教什么？

它适合串联讲解模拟环境、规则基线、行为克隆、强化学习、CTDE、配对评测、数据隔离、模型卡、发布和治理。相比只展示一段训练代码，它更适合解释一个模型怎样从实验走向可审计决策。

### 15. 推荐怎样安排学习顺序？

1. 观察蜂群世界和规则策略；
2. 用相同种子比较策略；
3. 理解训练、验证、选型和最终测试的区别；
4. 查看失败的 M10–M12 为什么没有晋级；
5. 查看 M14 如何通过结构性安全监督器改善结果；
6. 查看 M15 如何把比赛结果转化为可追溯的推荐或拒绝。

### 16. 学习者需要先掌握 PPO 或 CTDE 吗？

不需要。先理解“策略是什么”“公平考试是什么”“为什么最终测试不能参与调参”更重要。算法细节可以在建立这些概念后再学习。

### 17. 失败实验为什么也保留？

因为失败说明策略在哪些条件下不可靠，也能防止团队重复犯错或只挑选有利结果。M10–M12 没通过预先声明的门槛，它们不是被删除的废料，而是促成 M14 结构性改进的证据。

### 18. 可以把它直接作为课程产品使用吗？

可以作为课程素材或实验环境，但当前项目没有完整交付课程、练习、教师后台或学习效果验证。正式教学应用仍需教师设计目标、作业、评价标准和支持材料。

## 四、研究、训练与评测阶段

### 19. SweetGold 支持哪些策略或训练方式？

项目包含可解释的规则策略，以及行为克隆（BC）、PPO、集中训练分散执行（CTDE）等可选学习流水线。当前最新正式晋级策略是 M14 `hierarchical-return-ctde`。

### 20. M14 的正式结论是什么？

在六种环境分布、每种 50 个未参与训练或选型的最终种子上，M14 达到 100% 蜜蜂存活、0% 无效动作；相对 Assignment 的蜂蜜中位数为 148.47%，最差场景为 101.16%。这些结论只适用于已声明的模拟场景与协议。

### 21. 为什么不能继续用以前的最终种子调参？

一旦看过最终结果，这些种子就不再是“未见过的最终考试”。用它们修改模型、门槛或选择策略会造成信息泄漏，使新结论失去独立性。新研究必须预留全新的验证和最终种子范围。

### 22. 什么是“提前声明门槛”？

在查看正式最终结果前，先写清成功条件，例如最低存活率、最大无效动作率、产量改进和置信区间要求。这样可以避免看到结果后移动标准，让候选“刚好通过”。

### 23. 为什么 M7 明明产量更好却被拒绝？

因为它的无效动作率为 1.056%，超过了预先设定的 1% 门槛。SweetGold 的晋级是多约束判断，不能用更高产量抵消已声明的安全或质量失败。

### 24. M14 是否重新训练了 M8 的神经网络？

没有。M14 复用 M8 的行动者权重，并在外部加入确定性的返航、存蜜和充能监督器。新策略身份由共享权重、监督器代码及其注册参数共同定义。

### 25. 如何区分一次普通实验和正式评测？

普通实验可用于探索、调试和形成假设；正式评测则需要固定配置、预先声明门槛、未消费的最终种子、完整运行清单、隔离检查、可追溯产物和明确通过/拒绝决策。

### 26. 我可以加入新算法或新训练课程吗？

可以提出，但维护期内不应直接开工。先说明具体研究问题、为何现有策略不能回答、训练与计算预算、验证/最终种子范围、成功和安全门槛，以及结果无论成功失败如何记录。

### 27. SweetGold 能替代 PettingZoo、RLlib、BenchMARL 或 Isaac Lab 吗？

不能，也不应该。SweetGold 更适合作为多智能体策略的评测、证据和晋级层：接收外部环境或训练器产生的候选，再输出可追溯的比较与决策，而不是重新构建通用训练或物理仿真平台。

## 五、安装、运行与工程维护阶段

### 28. 最低运行要求是什么？

基础功能要求 Python 3.10+。训练学习策略需要额外安装 `requirements-ml.txt` 中的 PyTorch 依赖；基础模拟器不应因此强制依赖 ML 环境。

### 29. 如何获得已晋级模型？

```bash
python3 main.py models list
python3 main.py models download
python3 main.py models verify
```

模型注册信息包含不可变下载地址、文件大小、SHA-256、许可证和模型卡。下载后应先验证，再加载。

### 30. CPU、Apple MPS 和 NVIDIA CUDA 怎样选择？

ML 命令支持显式选择设备；`auto` 通常按 CUDA、MPS、CPU 的顺序选择可用后端。指定设备不可用时不应静默回退。GPU 也不保证更快：当前小型 BC 工作负载在 M1 Pro 上测得 CPU 约比 MPS 快 6.4 倍，因此应先 profiling 再决定云 GPU 投入。

### 31. 本地 Arena 可以部署给多人使用吗？

当前 HTTP 服务是研究和演示工具，没有经过多租户、身份、权限、网络防护、持久化运维和服务等级方面的生产加固。若要部署给多人或暴露公网，需要单独的安全与产品化工作。

### 32. 出现结果无法复现时，优先检查什么？

- Git 提交和配置是否一致；
- Python、可选 ML 依赖和硬件后端是否一致；
- 种子清单和场景参数是否一致；
- 模型文件大小与 SHA-256 是否通过；
- 是否混入未跟踪的本地数据、权重或旧运行产物；
- 请求的加速设备是否发生错误或隐式变化。

### 33. 哪些文件才是权威事实来源？

模型身份与摘要看 `registry/models.json`，正式审计看 `registry/audits.json`，实验和种子范围看 `experiments/*.json`，策略证据看 `docs/models/` 与发布说明。`runs/`、本地权重、生成数据集和虚拟环境通常只是本地产物，除非被正式注册或发布。

### 34. 修复 Arena 后，只看页面能打开就够了吗？

不够。至少应实际验证实时 Run、暂停、错误反馈、比赛进度与完成状态、结果显示、语言切换和受影响的响应式布局；还要确保实时单步请求不会重叠，前端错误不会被吞掉。

## 六、贡献、版本与发布阶段

### 35. 当前欢迎哪些贡献？

优先欢迎范围明确的缺陷、安全、兼容性、安装或模型下载修复、可复现性和文档修正，以及小型回归测试。大规模重构、新架构和宽泛产品扩展需先达成范围共识。

### 36. 提交 PR 时最重要的要求是什么？

保持改动聚焦，解释用户影响，补充相应测试，保护确定性和产物兼容性，不使用已消费的最终种子调参；用户可见行为变化时同步更新英文与简体中文文档及变更记录。

### 37. 为什么中英文文档要同步？

英文和简体中文都是正式产品界面。行为、命令、发布事实或用户指引只更新一种语言，会形成两个互相冲突的事实来源。

### 38. 代码完成、PR 合并和正式发布是一回事吗？

不是。开发完成表示功能与验证已就绪；发布准备还要检查文档、版本、产物、哈希和干净环境；正式发布则涉及标签、Release 和对外承诺，需要明确授权。

### 39. 什么情况下应该发软件版本或模型版本？

完整新用户能力通常对应 `v1.x.0`；缺陷、安全、兼容性或打包修正对应 `v1.x.y`；不兼容接口或产物契约才考虑 `v2.0.0`。模型发布是事件驱动的：只有新模型晋级、模型被替换、格式不兼容，或许可证/安全修复时才需要新模型版本。

## 七、采用、商业与合作阶段

### 40. SweetGold 已经是商业产品了吗？

不是。当前最准确的描述是：一个具有商业假设的开源研究与工程项目。它已有明确受众和潜在应用，但尚未证明付费需求、重复采购或真实行业业务结果。

### 41. 它最可能从哪里开始产生收入？

距离现有能力最近的是教育、工作坊、实验课程、部署支持，以及面向既有仿真环境的评测与晋级工具包。垂直仿真合作更接近联合开发；托管式多用户平台机会更大，但离当前产品也最远。

### 42. 可以直接用于仓储机器人、无人机或交通系统吗？

不能直接使用。SweetGold 展示了任务分配、局部执行、能量管理、同场景评测和证据工作流，但没有提供真实动力学、传感器、通信、时延、碰撞认证、法规或车队集成。可迁移的是方法和工作流，不是蜂群策略本身。

### 43. 如果企业想试点，第一步应该是什么？

先定义一个成本明确的问题，例如评测耗时过长、策略审批不可追溯或回归场景容易遗漏；然后用一个真实或标准外部环境验证 SweetGold 的证据工作流能否降低时间、缺陷或审计工作量，而不是先建设通用平台。

### 44. 什么样的信号说明值得继续产品化？

- 多位独立用户反复描述同一个高成本问题；
- 用户能在没有作者陪同的情况下运行并带回真实产物；
- 工作流离开 BeeSim 后仍能创造价值；
- 设计合作伙伴愿意投入时间、数据、集成权限或预算；
- 评测时间、缺陷、审批时间或审计工作量出现可衡量下降。

### 45. 什么信号意味着应该暂停投入？

如果外部反馈只停留在“蜜蜂演示很有趣”、Star 或口头赞赏，每次采用都依赖作者亲自操作，离开 BeeSim 后价值消失，或潜在用户不愿投入任何真实资源，就不应继续扩大产品范围。

### 46. Apache 2.0 是否允许别人复制或商业使用？

一般允许使用、修改、再分发和商业利用，但需遵守许可证、声明和修改标记等要求；许可证也不自动授予品牌或商标使用权。具体争议应咨询专业律师，不应把项目 FAQ 当作法律意见。

### 47. 开源后项目还能形成什么防御能力？

防御能力更可能来自可信上游、维护者信誉、真实场景与失败知识、适配器生态、双语教学、客户上下文，以及比自行搭建更省事的集成、托管和支持，而不是隐藏代码。

## 八、安全、证据与责任边界

### 48. SweetGold 所说的“安全”是什么？

当前主要指模拟环境内可测量的行为约束，例如蜜蜂存活率、无效动作率、能量管理和场景门槛。它不等同于现实机器人功能安全、网络安全认证、合规认证或对现实人身财产风险的保证。

### 49. M15 会自动替企业做最终决策吗？

M15 在给定目标、候选策略和约束下，确定性地推荐合格策略，或明确返回“没有合格策略”，并链接原始证据。它是可审计的决策辅助工作流，不替代组织责任人、领域专家、风险审批或现实部署验证。

### 50. 为什么“没有合格策略”也是有效结果？

因为约束优先于强行给出答案。如果所有策略都违反最低存活率或最大无效动作率，明确拒绝比推荐“相对最好但仍不合格”的策略更诚实，也更符合治理和审计需要。

### 51. 一个模型文件通过 SHA-256 校验，是否说明它安全可靠？

不是。哈希校验只说明文件与注册的字节内容一致，没有在传输或安装中被意外替换。它不证明模型效果、公平性、鲁棒性、来源合法性或适合某个现实用途；这些需要模型卡、评测、许可证和部署审查共同判断。

### 52. 哪些说法目前不应该对外宣称？

- “SweetGold 已经能控制真实机器人或无人机”；
- “M14 在任何未知环境中都可靠”；
- “一次 Arena 联赛证明了生产级鲁棒性”；
- “本地 Arena 是安全的企业多用户平台”；
- “已有经过验证的付费客户和商业模式”；
- “使用 GPU 一定更快”；
- “哈希通过就说明模型安全且适用”。

### 53. 对外介绍 SweetGold 最稳妥的一句话是什么？

> SweetGold 是一个以蜂群模拟为参考环境、面向多智能体策略的开源评测与证据基础设施；它展示如何公平比较、审慎晋级、可靠分发并审计策略，但还不是现实行业的生产控制系统。

## 九、问题分流与提问模板

### 54. 遇到问题时应该提供哪些信息？

请尽量提供：

- 你的目标：体验、教学、复现实验、开发、评测、集成还是部署；
- Git 提交或软件版本；
- 操作系统、Python 版本、CPU/MPS/CUDA 设备；
- 完整命令与可复现步骤；
- 期望结果和实际结果；
- 相关配置、种子范围、错误信息和运行产物路径；
- 模型名称、大小和 SHA-256 校验状态；
- 这是否涉及正式最终评测或已发布结论。

### 55. 不同问题应该流向哪里？

| 问题类型 | 建议处理方式 |
| --- | --- |
| 不理解项目或术语 | 先查入门指南、术语表和本 FAQ |
| 安装、运行、模型下载失败 | 提交可复现的 Bug，附环境、命令和错误 |
| 结果无法复现 | 附提交、配置、种子、设备、模型哈希和产物 |
| 想新增算法或产品功能 | 先提交研究/产品提案，不直接提交大规模实现 |
| 发现安全问题 | 走私密安全报告渠道，不公开泄露细节 |
| 想开展企业或研究合作 | 先描述真实环境、现有流程、失败成本、负责人和成功指标 |
| 想正式发布版本 | 区分开发完成、发布准备和正式发布，并取得明确授权 |

## 维护说明

本 FAQ 应随以下事实变化同步更新：最新软件版本、最新晋级策略、最新产品工作流、最新工程里程碑、维护状态、正式评测结果、命令、模型分发方式和安全边界。任何对外声明都应优先引用注册表、实验配置、模型卡、审计记录与正式发布说明，而不是旧对话或本地临时产物。
