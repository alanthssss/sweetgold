# SweetGold v1.2.0

[English](v1.2.0.md) | [简体中文](v1.2.0.zh-CN.md)

SweetGold v1.2.0 以可审计策略决策、硬件可移植 ML、平权中英文档和公开宣传站，
完成当前特性开发周期。

## 亮点

- M15 运行配对种子 Arena 联赛，应用明确的 `balanced`、`yield` 或 `safety` 目标，
  执行存活与无效动作约束，并写出相互链接的 JSON 和 Markdown 决策证据。
- M16 为 ML 命令增加明确的 `auto`、`cpu`、`mps`、`cuda` 选择，拒绝静默回退，
  并在运行清单记录硬件。
- 经过加速器同步的 BC 计时与吞吐量让硬件决策建立在证据上；M6 BC+PPO 和 M7 CTDE
  冒烟工作流均在 Apple MPS 通过。
- 中英文 README、交接、产品设计、变更日志、发布说明、模型卡和运行文档拥有平等入口。
- 双语项目站通过 GitHub Pages 持续发布到 <https://alanthssss.github.io/sweetgold/>。

## M15 可审计决策

```bash
python3 main.py arena-agent \
  --strategies assignment greedy scout \
  --objective balanced \
  --min-bee-survival 0.9 \
  --max-invalid-action-rate 0.01 \
  --episodes 10 --seed 42
```

相同产物和策略产生确定性决策。当所有候选违反约束时，系统保留明确的“没有合格策略”结果。
小规模联赛用于演示工作流，不能替代 M14 跨分布鲁棒性审计。

## M16 硬件可移植性

```bash
.venv-ml/bin/python main.py hardware --device auto
.venv-ml/bin/python main.py pipeline --config experiments/smoke.json --device mps
```

第一轮固定 20 回合、三个 epoch 的 BC 冒烟负载中，Apple M1 Pro CPU 用时 0.5774 秒、
吞吐 138,355 样本/秒；MPS 用时 3.6764 秒、吞吐 21,730 样本/秒。这个小负载不足以
抵消加速器调度成本，因此在 profiling 证明适合前暂缓 AWS CUDA。

## 模型与兼容性

v1.2.0 没有晋级新策略，也不发布新检查点。M14 `hierarchical-return-ctde` 仍是最新晋级
策略，继续使用已验证的 [`models-v2`](https://github.com/alanthssss/sweetgold/releases/tag/models-v2)
模型目录。现有模型 ID、注册记录、Arena 产物和 CLI 命令保持兼容。

## 验证

```bash
python3 main.py --version
python3 -m unittest discover -s tests -v
python3 main.py models download
python3 main.py models verify
```

源码使用 Apache-2.0。单独分发的模型产物继续使用声明的 Apache-2.0 条款和模型卡限制。

## 项目状态

v1.2.0 后暂停新特性开发。维护范围包括关键缺陷、安全、兼容性、可复现性、文档和发布运行。
未来 CUDA 运行或研究里程碑需要明确需求、预算、验收门槛，并在适用时使用未消费评测种子。
